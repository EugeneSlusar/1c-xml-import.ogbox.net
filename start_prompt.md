\# Проект: загрузка УПД XML в 1С:Управление торговлей 11.5



Нужно разработать внешнюю обработку 1С `.epf`, которая получает XML-файл УПД/ЭДО, разбирает его, сопоставляет данные со справочниками 1С и создаёт документ \*\*«Реализация товаров и услуг»\*\* в \*\*1С:Управление торговлей 11.5\*\*.



Работаем как с нормальным Git-проектом через VS Code + Codex. Исходники обработки должны храниться в текстовом виде (`.bsl`, XML метаданных/форм), а `.epf` должна собираться из исходников.



Не пытайся решать задачу изменением типовой конфигурации.



\---



\## 1. Целевая конфигурация



Основная и единственная целевая конфигурация для создания документов:



\*\*1С:Управление торговлей (базовая)\*\*

Редакция 11

Версия конфигурации: \*\*11.5.24.43\*\*



Платформа на машине клиента ранее была:



\*\*1С:Предприятие 8.3.27\*\*



База файловая.



Нельзя рассчитывать на возможность использования расширений `.cfe`.



Итоговое решение должно быть самостоятельной внешней обработкой:



`ЗагрузкаУПД.epf`



Она не должна изменять типовую конфигурацию.

\# 3. Главная цель



Минимальный рабочий сценарий:



1\. Пользователь открывает `ЗагрузкаУПД.epf`.

2\. Нажимает \*\*«Выбрать XML»\*\*.

3\. Выбирает XML УПД.

4\. Обработка читает XML.

5\. Проверяет его структуру.

6\. Извлекает шапку документа.

7\. Извлекает продавца.

8\. Извлекает покупателя.

9\. Извлекает товарные строки.

10\. Извлекает НДС и суммы.

11\. Показывает всё пользователю на форме.

12\. В УТ сопоставляет данные со справочниками.

13\. Пользователь нажимает \*\*«Создать реализацию»\*\*.

14\. Создаётся `РеализацияТоваровУслуг`.

15\. Документ записывается.

16\. Документ НЕ проводится автоматически.

17\. Созданный документ открывается пользователю для проверки.



Главный принцип:



\*\*сначала безопасно создать и показать документ, а не автоматически провести его.\*\*

\# 5. Важный нюанс по цене



Не предполагай, что:



`ЦенаТов × КолТов = СтТовБезНДС`.



В тестовом XML:



```text

2.18 × 5000 = 10900.00

```



при этом:



```text

СтТовБезНДС = 10380.95

НДС = 519.05

СтТовУчНал = 10900.00

```



Поэтому структура данных парсера должна хранить отдельно:



\* количество;

\* цену из XML;

\* сумму без НДС;

\* ставку НДС;

\* сумму НДС;

\* сумму с НДС.



Не пересчитывай и не уничтожай исходные значения при парсинге.



При создании документа УТ нужно будет корректно определить режим цены/НДС, чтобы документ в 1С в итоге дал те же суммы.



Если в УТ есть штатные механизмы расчёта НДС — используй их, а не дублируй бухгалтерскую математику вручную без необходимости.

\# 9. Валидация



До создания документа проверить минимум:



\* XML удалось прочитать;

\* существует `Документ`;

\* существует номер документа;

\* существует дата;

\* найден продавец;

\* у продавца есть ИНН;

\* найден покупатель;

\* у покупателя есть ИНН;

\* присутствует хотя бы одна строка товаров/услуг;

\* количество имеет корректный числовой формат;

\* денежные значения прочитаны корректно;

\* итоговые суммы присутствуют.



Проверять контрольное равенство:



```text

СуммаБезНДС + СуммаНДС ≈ СуммаСНДС

```



учитывая допустимые округления до копеек.



Не считать ошибкой само по себе то, что:



```text

ЦенаТов × Количество

```



не равно сумме без НДС.
